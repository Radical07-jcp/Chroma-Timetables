# Chroma Timetables v1.0.1 — Revamp Account

This package is the complete v1.0.1 pass against the supplied Codespace build.

## Fixed / shipped

### Branding and typography
- CHROMA remains Press Start 2P, gold.
- TIMETABLES remains Press Start 2P, mint, resized to visually match CHROMA.
- UI typography is explicitly wired to Space Grotesk through Jetpack Compose Google Fonts.
- Bundled Montserrat is only an offline fallback; the UI is no longer intentionally using the Android system font.

### In-app logo
- Uses the newly supplied Chroma logo.
- Transparent background is enforced for the external black regions and the black-filled calendar/graph areas.
- Theme-aware contrasting shadow is applied in Compose.
- Launcher icon files were not changed in this pass.

### Visual system
- Material 3 Light / Dark / Black themes retained.
- Accent preferences retained.
- Shared brand chrome and modern surface hierarchy extended across the main workflow.
- PLAN / VALIDATE / OPTIMIZE tags use separate semantic colors.
- Long explanatory/formal body copy uses justified alignment where appropriate.
- Import-success reference visual language is carried into import metrics, action hierarchy, cards, and workflow presentation.

### Timetable creation
- New timetable flow is now:
  1. Choose timetable type.
  2. Define periods.
  3. Import a new ZIP.
  4. Generate.
- Every new timetable therefore starts from an explicit source-data import.
- Existing generation validation remains automatic.

### Source data replacement
- A new ZIP replaces the current working dataset instead of silently reusing an older dataset.
- Current imported data can be explicitly cleared.
- Saved timetable versions are not deleted when the working dataset is replaced or cleared.

### Data isolation
- Each generated/imported timetable stores a source-data snapshot.
- Older timetables remain displayable/exportable/repairable/optimizable after a different ZIP is imported.
- Teacher availability changes are propagated into saved timetable snapshots so repair/optimization can respond to changed preferences without rebuilding from scratch.

### Repair / optimization
- Existing minimal-change repair/optimization remains intact.
- Local session moves remain intact.
- Direct teacher/session swaps remain intact.
- Current teacher availability changes are consumed by the timetable being repaired/optimized.
- Optimization produces a new version in the same timetable lineage and re-validates the result.

### Version deletion
- Every timetable history version now has its own delete action.
- Deleting the root removes the complete timetable lineage.
- Deleting a derived Repair/Optimize version removes only that version.

### Release metadata
- Android versionName: 1.0.1
- Android versionCode: 2
- Settings/About updated to Chroma Engine v1.0.1.
- CHANGELOG.md updated.

## Explicitly preserved

- Repair engine.
- Optimization engine and change budget.
- Export.
- Existing Light/Dark/Black theme preference system.
- Existing accent preference system.
